# Путешествие по Политеху

Игра-путешествие по истории ИРНИТУ. Экран загрузки и главное меню с пятью
разделами:

- **Галерея** — шкала лет и фотоальбом выпусков с перелистыванием, по клику
  фото открывается крупно;
- **История** — растущее дерево направлений: этапы на стволе, ветки
  направлений, по клику — таймлайн направления;
- **Музей** — анфилада залов с витринами, по клику экспонат крупно с
  музейной этикеткой;
- **Отзывы** — лента воспоминаний выпускников с фильтрами по направлениям и
  форма «Оставить отзыв» (пока без отправки на сервер);
- **День в Политехе** — 3D-прогулка по университету с гидом, пока заглушка
  «Скоро».

И окно «Об игре».

Чистые HTML, CSS и JavaScript — без сборки, зависимостей и обращений в сеть.

## Как запустить

Откройте `index.html` двойным щелчком. Всё работает по протоколу `file://`:
внешних запросов нет, шрифты и картинки лежат рядом, интернет не нужен.

Если понадобится отдать страницу по сети, подойдёт любой статический сервер:

```
python -m http.server 8000
```

и затем `http://localhost:8000` в браузере.

## Где что менять

### Тексты

Все надписи собраны в `js/config.js`, объект `texts`. В разметке текста нет:
элементы помечены атрибутом `data-text`, значение подставляется по ключу.

```js
texts: {
  title: 'Путешествие по Политеху',
  tagline: 'Игра-путешествие по истории университета',
  galleryTitle: 'Галерея',
  ...
}
```

Достаточно исправить строку. Ключи трогать не нужно — на них ссылается
разметка.

Там же лежат `loaderMs` — сколько миллисекунд идёт полоса загрузки — и
`reviewEndpoint`, адрес для отправки отзывов (см. «Форма отзыва и бэкенд»).

Слова после чисел («3 зала», «5 отзывов», «2 поля») склоняются функцией
`Screens.plural`; три формы слова лежат в `texts` рядом с остальными
надписями, например `reviewForms: ['отзыв', 'отзыва', 'отзывов']`.

### Цвета и шрифты

`css/variables.css`, блок `:root`. Остальные стили цветов не содержат, только
ссылаются на переменные, поэтому правка здесь меняет оформление целиком.

| Переменная                              | За что отвечает                   |
|-----------------------------------------|-----------------------------------|
| `--c-page`                              | фон вокруг сцены                  |
| `--c-bg`                                | фон самой сцены                   |
| `--c-surface`                           | карточки, кнопки, окно «Об игре»  |
| `--c-ink` / `--c-ink-dim`               | основной и второстепенный текст   |
| `--c-line`                              | рамки и разделители               |
| `--c-blue` / `--c-blue-deep`            | акцент и акцент при нажатии       |
| `--c-teal`                              | левый край градиента заголовка    |
| `--g-title`                             | сам градиент заголовка            |
| `--c-grid` / `--c-circuit` / `--c-code` | сетка, дорожки и столбцы на фоне  |
| `--c-photo` / `--c-photo-ink`           | серая заглушка вместо фото        |
| `--font-ui` / `--font-mono`             | шрифты                            |
| `--branch-<type>`                       | цвета веток дерева истории        |

Ниже в том же файле — метрики сцены (`--mode-w`, `--title-size`, `--menu-gap`
и другие). Значения в `:root` действуют для альбомной ориентации; для
портретной их переопределяет `applyLayout` в `js/screens.js`. Все разделы,
кроме меню и заглушки, свёрстаны только под альбомную сцену: в вертикальном
окне она просто уменьшается.

Шрифты лежат в `assets/fonts/` и подключаются в `css/fonts.css`. Чтобы
заменить шрифт, положите туда woff2, опишите `@font-face` и поменяйте
`--font-ui` или `--font-mono`.

### Картинки

Файлы — в `assets/img/`, пути к ним — в `js/config.js`:

```js
images: {
  mark: 'assets/img/ipolytech.svg',
  logo: 'assets/img/logo-irnitu.png',
}
```

Положите новый файл в `assets/img/` и поправьте путь. В разметке пути не
дублируются: у тегов `<img>` стоит `data-img`, источник подставляется из
конфига.

## Данные разделов

Фото, подписи, этапы и направления, залы музея и отзывы лежат отдельно от кода, в
папке `js/data/`. Это обычные `.js`-файлы, а не `.json`: браузер не даёт прочитать
JSON по `file://`, а скрипт подключается без ограничений.

Шкала лет, страницы альбома, дерево истории, залы, витрины и фильтры отзывов в
коде не прописаны — всё считается из этих файлов. Достаточно поправить данные и обновить страницу.

Пара правил, чтобы файл не сломался:

- каждая запись — в фигурных скобках, после каждой записи запятая;
- строки — в одинарных кавычках `'…'`. Если в тексте нужен апостроф,
  поставьте перед ним обратную косую черту: `'Д\'Артаньян'`. Обычные
  русские кавычки «ёлочки» можно писать как есть;
- пути к фото — от `index.html`, через `/`, например
  `'assets/gallery/1960/01.jpg'`. Пустой путь `''` — вместо фото серая
  заглушка.

Если после правки страница перестала открываться дальше загрузки, скорее
всего, пропущена запятая или кавычка. Ошибку с номером строки покажет консоль
браузера (F12 → Console).

### Галерея — `js/data/gallery.js`

```js
window.GALLERY_DATA = [
  {
    year: 1960,
    photos: [
      { src: 'assets/gallery/1960/01.jpg', caption: 'Общее фото выпуска', direction: 'Горное дело' },
      { src: '', caption: 'Подпись к фотографии', direction: 'Геология' },
    ],
  },
  ...
];
```

**Добавить год.** Скопируйте блок `{ year: …, photos: [ … ] },` целиком и
поменяйте год. Порядок в файле не важен: шкала сортирует годы сама. На
шкале одновременно видно девять лет, остальные открываются стрелками.

**Добавить фото.** Положите файл, например, в `assets/gallery/1960/` и
добавьте строку в `photos` нужного года:

```js
{ src: 'assets/gallery/1960/05.jpg', caption: 'Кто на снимке, где и когда', direction: 'Горное дело' },
```

Фото идут в альбоме в том порядке, в каком записаны. Первое фото года
попадает на титульную страницу выпуска, остальные — по три на страницу.
Число страниц и разворотов, счётчики «N фотографий» и миниатюры в просмотре
пересчитываются сами. Подпись и направление показываются при просмотре фото
крупно.

### История — `js/data/history.js`

```js
window.HISTORY_DATA = {
  stages: [
    { year: '1920', name: 'Название этапа университета' },
    ...
  ],

  branches: [
    {
      title: 'Название направления',
      type: 'mountain',
      items: [
        ['1930', 'Событие с годом'],
        ['', 'Событие, год которого пока не известен'],
      ],
      subbranches: [
        { title: 'Название подветки', items: [ ['1973', 'Событие'] ] },
      ],
    },
    ...
  ],
};
```

- `stages` — этапы университета на стволе, снизу вверх. Год — строка; этап
  длится до года следующего этапа.
- `branches` — направления. `title` показывается на дереве и в фокусе, его же
  используют другие разделы (см. ниже).
- `type` — ключ направления. По нему берётся цвет ветки: переменная
  `--branch-<type>` в `css/variables.css`. Если переменной нет, ветка будет
  цвета ствола.
- `items` — события в формате `[год, название]`. Год — строка.
- `subbranches` — подветки, необязательно: `title` и `items`.

Файл перенесён из прототипа дословно; дубли и события без года оставлены
как есть.

**События без года.** Если первый элемент пустой (`''`), событие попадает в
блок «Год уточняется» внизу своей карточки, а на ветке показывается полым
листом. Впишете год — событие перейдёт на таймлайн.

**Где растёт ветка.** Ветка отходит от этапа, в который попал самый ранний
год её событий и подветок. Направления совсем без годов растут над
последним этапом, пунктиром, под чипом «Год уточняется». Высота дерева,
этапы, ветки, подписи, счётчики и карточки считаются из этих данных.

**Добавить направление.** Скопируйте блок одного направления внутрь
`branches`, поменяйте поля и добавьте цвет `--branch-<type>`. Кнопки
«Предыдущее» и «Следующее» идут по порядку в файле, по кругу.

Скорость роста и камеры — константы `GROW` и `FOLLOW` в начале
`js/history-tree.js`.

**Откуда берут направления другие разделы.** Фильтры ленты отзывов и список
в форме отзыва строятся из `title` направлений этого файла, поле `direction`
у фото галереи и отзывов должно совпадать с `title` дословно. Если направление
не найдено, игра работает дальше, а в консоли браузера (F12 → Console)
появляется предупреждение с названием и местом в данных. Переименовали
направление — поправьте `direction` в `js/data/gallery.js` и
`js/data/reviews.js`.

### Музей — `js/data/museum.js`

```js
window.MUSEUM_DATA = [
  {
    name: 'Название зала',
    years: '1930 — 1945',
    about: 'Описание зала.',
    exhibits: [
      {
        name: 'Название экспоната',
        year: 1932,
        about: 'Описание экспоната.',
        photo: 'assets/museum/hall1/01.jpg',
        source: 'Откуда экспонат',
        inventory: '1001',
      },
    ],
  },
  ...
];
```

- `years` — строка, писать можно как угодно: `'1930 — 1945'`,
  `'с 2010'`.
- `source` и `inventory` необязательны: если оставить `''`, строк
  «Источник» и «Инв. номер» на этикетке не будет. Строка «Зал» есть всегда.

**Добавить зал.** Скопируйте блок зала целиком и поменяйте тексты. В
анфиладе появится ещё одна арка; номер «Зал 06 из 06» посчитается сам. Если
залов больше шести, ряд арок прокручивается вбок.

**Добавить экспонат.** Скопируйте блок экспоната внутрь `exhibits` нужного
зала. Витрины идут по три в ряд, две строки на экране; если экспонатов больше
шести, сетка прокручивается. Номер вида «Экспонат 2.03» и счётчик «N
экспонатов в зале» считаются сами.

### Отзывы — `js/data/reviews.js`

```js
window.REVIEWS_DATA = [
  {
    name: 'Имя Фамилия',
    year: 1998,
    direction: 'Горное дело',
    date: '2026-10-24',
    text: 'Текст отзыва.',
    photo: 'assets/reviews/01.jpg',
  },
  ...
];
```

- `direction` — дословно как поле `title` направления в `js/data/history.js`,
  иначе отзыв не попадёт в фильтр этого направления (во «Все отзывы» он
  попадёт всё равно).
- `date` — в формате `ГГГГ-ММ-ДД`; лента идёт от новых к старым, порядок в
  файле не важен.
- `photo` необязательно. Если поля нет, у отзыва нет фото; пустая строка
  `''` — серая заглушка.
- Инициалы в кружке берутся из первых букв `name`.

**Добавить отзыв.** Скопируйте блок одного отзыва и поменяйте поля. Лента
показывает по девять карточек, остальные — по кнопке «Показать ещё».

## Форма отзыва и бэкенд

Сейчас форма никуда ничего не отправляет. По «Отправить отзыв» она только
проверяет поля и показывает экран «Спасибо»; выбранное фото показывается
как предпросмотр в браузере и никуда не загружается.

Всё, что относится к отправке, собрано в одной функции — `submitReview()` в
`js/review-form.js`, над ней пометка «СЮДА ПОДКЛЮЧАЕТСЯ БЭКЕНД». Функция
получает готовый отзыв:

```js
{ name, year, direction, text, date, photo }
```

`photo` — выбранный файл (`File`) или `null`.

Чтобы подключить сервер:

1. Впишите адрес в `js/config.js`:

   ```js
   reviewEndpoint: 'https://example.ru/api/reviews',
   ```

2. В `submitReview()` отправьте отзыв на `CONFIG.reviewEndpoint` и верните
   `Promise` — пример с `fetch` и `FormData` лежит в комментарии над
   функцией. Экран «Спасибо» показывается, когда `Promise` выполнится.

3. Откройте игру через веб-сервер (см. «Как запустить»), а не двойным
   щелчком: со страницы, открытой по `file://`, браузер может не пустить
   запрос к серверу.

Новые отзывы в ленте сами не появятся: лента читает `js/data/reviews.js`.
Опубликовать отзыв после модерации — значит добавить его в этот файл (или,
когда будет бэкенд, научить ленту загружать отзывы с сервера).
